# 物品禁用黑名单

## 使用方法

只需修改 `kubejs/config/disabled_items.json`，将完整物品 ID 填入 `items`：

```json
{
  "items": [
    "bhc:god_apple",
    "minecraft:diamond_sword"
  ]
}
```

这是示例，不是默认禁用项。默认 `items` 为空，任何物品都不会被禁用。
使用游戏内 F3+H 显示高级提示，查看物品 ID。只支持完整 ID，不支持标签、
通配符或按 NBT 禁用；同一个 ID 的所有 NBT 变体均被禁用。重复 ID 自动去重。
不得填入 `minecraft:air`。JSON 不允许注释或末尾多余逗号。

保存后 **完整退出并重启游戏/服务器**。不要仅使用 `/reload`、F3+T 或
`/kubejs reload_startup_scripts`：黑名单与 Forge 监听器在启动时加载。
联机环境将这三份脚本和配置同步到服务器及每个客户端；JEI 隐藏读取客户端配置。
将 ID 从数组删除并重启即可解除禁用，但之前清掉的物品不会恢复。

**先备份存档。清理是永久删除，包含已经持有的物品；不会发放补偿。**

## 脚本分工

- `startup_scripts/disabled_items.js`：读取并校验黑名单，在原生使用开始前拦截
  空气/方块/实体右键、使用开始、攻击和挖掘。
- `server_scripts/disabled_items.js`：移除以禁用物品为产出的配方，以 LootJS
  过滤所有匹配战利品表的产出，禁止拾取，并清理玩家持有物。
- `client_scripts/disabled_items.js`：JEI 隐藏禁用物品。

清理包含主背包、快捷栏、盔甲、副手、个人合成格、鼠标持有物、末影箱和
Curios 功能/装饰栏。个人合成格指玩家物品栏的 2×2 格，不包含已打开工作台
的 3×3 格。登录、重生、库存变化及每 tick 兜底检查。
只在实际清理后同步库存；默认空名单时不扫描。

## 边界

- 不注销物品注册、不删除物品对应的已放置方块，也不关闭机器本身。
- 不删除把这些物品当作输入的配方；只移除产生这些物品的配方。
- 不递归检查潜影盒、模组背包等物品 NBT 中的内部储物空间，也不扫描世界里
  全部箱子和机器库存；从中取到玩家库存时会清理。
- LootJS 过滤战利品表生成流程，不倒查此前生成的箱子，也不能保证后执行的
  模组自定义代码、非战利品表奖励、交易、任务奖励不会再次写入物品。
  原版凋灵之星及闪电苦力怕造成的苦力怕/骷髅/僵尸头颅掉落另有专用拦截。
- 脚本清理不能保证其他模组写入库存的那个瞬间完全没有物品，通常在库存
  变化通知或下一 tick 删除。标准使用事件已拦截，但模组绕过 Forge 事件
  的自定义行为需要另行适配。
- JEI 只隐藏物品列表，不等于物品从注册表删除，也不是隐藏所有含它的文字
  说明、特殊模组展示页或创造模式物品栏。
- 已有 OEI 统一规则可能把源 ID 替换成另一个 ID；要禁用最终获得的物品，
  应填写统一后的实际 ID。

## 验证

离线契约测试（不是 Minecraft/Forge 模拟器）：

```powershell
node tools/test_disabled_items.cjs
```

在备份后的测试存档临时禁用一个容易获取的物品，重启后验证 JEI、工作台与
烧炼输出、战利品表、拾取、`/give`、已有背包物品、副手/护甲及 Curios。
检查 `logs/kubejs/startup.log` 和 `server.log` 是否有脚本错误。
