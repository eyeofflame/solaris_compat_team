# 禁止矿石自然生成：设计

## 需求与范围

目标是让资源生产依赖 Solaris Resources 的魔法生产链，而不是自然挖矿。
用户已确认：只禁止矿石，不禁止普通地层；采用矿石识别、多层生成拦截、补充名单和热重载。

- 对所有维度中新生成的区块生效，覆盖原版和可识别的模组矿石。
- 原版范围包含煤、铁、铜、金、红石、青金石、钻石、绿宝石、下界金、下界石英及远古残骸，以及相应深板岩变体。
- 保留泥土、砂砾、花岗岩、闪长岩、安山岩及大型矿脉中的普通岩石。
- 不扫描或删除已经生成的矿石，不阻止玩家放置，也不影响物品、合成或现有法术生产链。
- 对新区块生成期间通过受支持入口放置的矿石一律拦截，包括结构装饰中的矿石；不处理结构宝箱中的物品。
- 不以方块名称包含 `ore` 为判定依据。

## 矿石识别

一个方块符合任一条件即视为矿石：

1. 属于显式原版矿石集合；
2. 属于当前服务端数据包提供的 `forge:ores` 方块标签；
3. 属于配置指定的额外矿石集合。

标签只判断最终生成方块，不把用于决定矿石可替换基底的标签视为矿石标签。
数据包标签重新加载后，后续生成应使用最新标签，不缓存过期的标签判断。

## 配置与热重载

新增独立文件 `config/solaris_resources/worldgen.json`，不改变现有原子文件格式：

```json
{
  "additionalOreBlocks": []
}
```

列表填写完整、已注册的方块 ID，例如 `examplemod:tin_ore`。这不是原版或 `forge:ores` 的替代列表；它只能补充矿石识别。

- 缺失文件时自动生成默认值；不覆盖已有文件。
- 字段必须是字符串数组；每项必须是合法且已注册的方块 ID；重复项去重。
- 非法文件整体拒绝更新并记录原因；保留上一次有效补充集合，首次失败使用空集合。
- 解析和方块注册表校验安排在注册完成后。
- `/solaris_resources_reload` 继续需要 2 级权限，支持控制台，并独立尝试原子配置和世界生成配置的加载。
- 保留原子成功/失败数量反馈，另外反馈世界生成配置是否更新成功；其中一类失败不阻止另一类加载。
- 世界生成线程使用不可变补充集合，通过一次原子引用替换发布更新，不共享正在修改的集合。
- 生效点为重载完成后的生成检查；已经检查过或已经生成的方块不追溯处理。在途区块可能含重载前规则的结果。

## 生成拦截架构

使用公共服务端逻辑与 Mixin，沿用项目已有 Mixin 配置。拦截层共享同一个矿石判定器，不各自维护名单。

### 1. 标准矿石 Feature

针对普通矿脉与散布矿石的最终放置目标拦截。
只跳过被识别为矿石的目标；非矿石目标继续原有流程。
不能整体移除 `underground_ores` 阶段，也不能因为 Feature 使用矿脉算法便禁止它。
一个配置包含矿石与非矿石目标时，必须只拦截矿石，不删除整个混合 Feature。

### 2. 原版大型矿脉

单独拦截原版噪声大型铁、铜矿脉产出的矿石及其自然生成的粗铁块、粗铜块。
粗铁块与粗铜块仅在大型矿脉生成分支视为待禁资源，不因此全局禁止这些方块的结构放置。
被跳过的矿脉资源位置保持正常基底，不生成空气洞；普通岩石继续生成。

### 3. 世界生成写入补充拦截

在 `WorldGenRegion` 的世界生成写入入口检查目标状态。
已识别矿石不写入，保持已有状态；返回表示未放置的结果，避免伪造成功。
此入口补充覆盖经它写入的自定义 Feature 和结构矿石，不注入一般 `Level.setBlock`，避免干扰正常游玩。
涉及直接写入区块而绕过该入口的标准矿石生成，由第一层拦截承担覆盖。

具体注入方法和签名在实现计划前通过 Minecraft 1.20.1 / Forge 47.4.10 映射源码确认。
核心注入必须在开发启动时验证应用成功；不能仅以 Java 编译通过宣称运行覆盖成立。

## 兼容性边界

对任意第三方模组不存在自动绝对覆盖承诺：

- 未加入 `forge:ores` 的矿石需要加入补充名单。
- 绕过所有受支持入口、直接写入区块数据的自定义生成器需要单独适配。
- 已生成区块中的重新生成、运行时矿石再生和玩家行为不纳入本次范围。
- 开发依赖中的 Ars Nouveau 需要检查其生成数据和标签，并作为模组兼容性验证样本；不假定它遵循某个入口。
- 不通过生成后扫描所有区块来弥补边界，不新增跨区块清除任务。

## 验证与验收

自动化测试覆盖：

- 原版显式名单、模组标签、补充名单三个来源的矿石识别，以及普通地层的放行。
- 默认配置生成、已有配置读取、重载、未知方块 ID、错误 JSON、错误字段类型及失败保留旧值。
- 重载后后续判定使用新不可变集合，并保留原子配置重载行为。
- 可隔离测试的拦截决策：矿石拒绝、非矿石放行、混合目标不整体跳过。

构建验证运行配置测试、项目测试和完整构建。
运行验证使用独立测试世界，不修改用户已有存档：

1. 验证 Mixin 加载，不出现注入失败。
2. 确认主世界与下界新生成区域的原版矿石被阻止；大型铁铜矿脉资源被阻止而普通地层保留。
3. 对 Ars Nouveau 矿石及一个补充名单目标验证自然生成拦截。
4. 验证 OP 和控制台重载，非 OP 无权执行；已有原子功能不回归。
5. 验证玩家正常放置矿石不被拦截；旧区块不被清理。

若环境无法执行实际世界生成验证，交付时必须明确列出未验证项，不能把配置单元测试或构建成功当作游戏内生成效果的证据。
