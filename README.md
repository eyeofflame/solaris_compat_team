# Solaris Resources
用魔法生产资源！

## 创造标签页

通过 `BlockRegistries.registerBlockItem(...)` 注册的方块物品会自动追加到 Solaris Resources
创造标签页中，默认和自定义 `BlockItem` 均支持，无需再手动填写标签页列表。
仅注册方块而未注册物品的内容不会自动出现；模型、名称和掉落规则仍需单独配置。

## 不稳魔力机械核心

机器只能竖直放置：传动杆朝上或朝下，不接受水平朝向，旋转与镜像也不会改变轴向。
正下方放一个机械动力的流体储罐后，右键机器会打开界面；下方没有储罐时右键不会打开。

界面模板是 `assets/solaris_resources/efm_ui/magic_core_i.ui`，其中的流体槽会自动接到下方储罐；
魔源槽显示机器自带的魔源存量，上限 800。机器实现了 Ars Nouveau 的魔源接口，
可被魔源继电器灌入或抽走；目前还没有消耗魔源的生产逻辑。

界面里那个开关（`sola_button_0`）控制"吸取魔力"，默认关闭，切换时动作栏会提示当前状态。
开启后每 20 tick 抽取以机器为中心 5×5×5 范围内所有玩家的全部魔力，按 1:1 转成机器魔源；
魔源已满时不会再去抽人，但单次吸取超过剩余容量的部分会被丢弃。

加工需要转速 ≥ 32 rpm：32 rpm 时一次 200 tick，256 rpm 时 20 tick，中间按转速线性变化，
更快也固定 20 tick；转速不足时停机但保留进度。每次完成消耗 1B 水和 15 魔源，
水从下方储罐抽取且必须是水（装了岩浆等其它液体视为没料）。界面里的 `sola_progress`
进度条显示当前进度。

机器有三个输出槽（对应界面控件 `sola_output_0` / `1` / `2`）：每个槽只接受一种物品、上限 64 个，
任何一个槽装满都会让机器停止加工，腾出空位后自动恢复。输出槽对外暴露 Forge 物品能力，
漏斗、管道和机械动力的装卸器都能把产物抽走，但**不能往里塞东西**。产出由
`config/solaris_resources/machine/magic_core_I.json` 配置，每次处理完成时掷一次 0~99，
按顺序找第一条命中的规则，只产出那一条：

```json
{
  "outputs": [
    { "chanceMin": 0,  "chanceMax": 2,  "item": "minecraft:iron_ingot", "countMin": 1, "countMax": 2 },
    { "chanceMin": 2,  "chanceMax": 6,  "item": "minecraft:gold_ingot", "countMin": 1, "countMax": 5 },
    { "chanceMin": 50, "chanceMax": 60, "item": "",                     "countMin": 1, "countMax": 9 }
  ]
}
```

- 三个槽固定三条规则；缺的条目按"未配置"补位（永不命中）。
- `chanceMin` 含、`chanceMax` 不含，取值 0~100 且必须 `min < max`；0~99 共 100 个落点。
- `item` 留空表示这个槽不产出；填了就必须是已注册物品 ID，否则整份文件被拒绝。
- `countMin`/`countMax` 是**含两端**的产出数量，取值 1~64 且必须 `min <= max`。
- 文件缺失时自动生成默认值；改完执行 `/solaris_resources_reload` 立即生效，坏文件保留上一份有效配置。
- 默认值就是旧行为：三条分支 0-2 / 2-6 / 50-60，数量 1-2 / 1-5 / 1-9，物品留空。

代码里想直接塞产物仍然可以调：

```java
boolean ok = addOutput(Items.IRON_INGOT, 4);   // 校验物品种类与 1..64 数量，整批放不下就返回 false
ItemStack leftover = insertOutput(stack);      // 能塞多少塞多少，返回余量
```

戴工程师护目镜看向机器时，转速低于 32 rpm 会在原有转速／应力信息下方多出一行红字
"应力不足：需要至少 32 RPM"。

## 法术范围预览

手持四本预设法术书，或 Ars Nouveau 施法工具当前选中的法术包含本模组效果时，
瞄准方块即可看到作用区域线框；切换法术槽后预览随之更新。
主手有相关效果时优先显示主手，否则检查副手。

- 水结晶：蓝色，命中方块周围的 3×3×3。
- 水分解：绿色，命中方块上方的 3×3×3。
- 原子组装：橙色，同上。
- 原子聚合：紫色，同上。

同一法术中多个效果共用区域时只绘制一次，采用第一个对应效果的颜色。
线框遵守地形遮挡，不替换原版方块选框。命中空气或实体、打开界面、隐藏 HUD 或旁观模式时不显示。
预览仅以准星命中方块为锚点：接触法术直接对应作用位置，弹射物等方式不预测最终落点。
实体类效果按实体包围盒与区域相交判定，不要求实体中心在线框内。

范围与效果识别验证：`gradle testSpellEffectRange`。

## 水转化与原子数量

水转化只消耗范围内独立的水源方块，每个成功移除的水源产出 4 份晶化水；
不消耗流水，也不处理含水方块。每份晶化水分解为 16 个不稳定氢原子和 8 个不稳定氧原子。

原子实体可以承载超过普通物品堆叠上限的数量，其总数以独立整数保存和同步，
不会为了拆堆改变组装时的实体分组与随机产量。聚合后的普通物品则按最大堆叠数量拆分掉落。
仍然有效的旧版原子实体存档可读取；旧版本已截断丢失的数量无法恢复。

水源筛选、原子数量存档/同步及聚合拆堆验证：`gradle runGameTestServer`。

## 原子转换配置

首次启动时会为每种原子生成 `config/solaris_resources/<path>.json`。
稳定原子与同类型的不稳定原子共用配置。例如 `iron.json`：

```json
{
  "convertedItem": "minecraft:raw_iron",
  "ratio": 8
}
```

`convertedItem` 为聚合后产出的物品 ID，`ratio` 为生成一个该物品所需的原子数。
物品 ID 必须存在，比例必须为非负整数；空物品 ID 或比例为 0 时不参与聚合。

编辑配置后执行 `/solaris_resources_reload` 即可立即生效，无需重启。
该指令需要 2 级权限，也可在服务端控制台执行。
已有背包或掉落中的原子会在下一次聚合时使用新规则。
失败项保留之前的有效配置（首次加载失败使用代码默认值），错误详情记录在日志中。
缺失的文件会重新生成默认配置；已有文件不会被覆盖。

开发验证：`gradle testAtomConfig test build`。

## 禁止自然矿石

新生成区块中的原版矿石、`forge:ores` 标签中的模组矿石都会被阻止生成；
普通地层（包括花岗岩、闪长岩、安山岩、凝灰岩和矿脉填充岩）会保留。
大型铁／铜矿脉中的矿石和粗矿块也会被过滤，但普通岩石不会变成空气。

可在 `config/solaris_resources/worldgen.json` 中补充未加入 `forge:ores` 的模组方块：

```json
{
  "additionalOreBlocks": [
    "examplemod:tin_ore"
  ]
}
```

配置文件缺失时自动生成；修改后执行 `/solaris_resources_reload`，后续生成检查立即使用新名单。
配置项必须是已注册方块 ID 的字符串数组。错误文件保留上一次有效配置并写入日志。
方块 ID 必须完整且规范，例如 `minecraft:gold_block`；不接受 `:gold_block` 或省略命名空间。

此功能只影响新区块生成，不清理旧区块，也不阻止玩家正常放置矿石或运行时使用 Feature。
结构装饰经受支持生成入口放置的矿石也会被阻止；结构宝箱里的物品不受影响。
热重载不追溯已经完成的生成检查，在途区块可能含重载前规则的结果。
未加入标签且未写入补充名单的自定义生成器，以及绕过受支持世界生成入口的特殊生成器，
需要单独适配。

独立验证命令：`gradle testWorldgenConfig testOrePolicy testAtomConfig test build runGameTestServer`。
测试数据包将 Ars Nouveau 的源质宝石块人工标记为矿石，仅用于验证模组方块识别；
这不代表 Ars Nouveau 自带该矿石生成，测试标签不会进入发布 JAR。
